### 1.3 설계 원칙

Plan의 D-1~D-8(단일 원천, 견본 1:1, 화면 축과 업무 축, 헤더 버튼과 드로어, 규정은 링크, 코드가 원천, 「」 라벨 검사, marked + DOMPurify)을 그대로 따르고 셋을 더한다.

| # | 원칙 | 이유 |
|---|------|------|
| D-9 | **검사 먼저**: `check_manual.py`와 매뉴얼 골격(헤딩 전부)을 먼저 만들고, 본문은 검사를 통과시키면서 쓴다 | 화면 이름 오기를 쓰는 즉시 잡는다. 마지막에 몰아서 고치지 않는다 |
| D-10 | **「」는 앱 화면에 나오는 글자 전용**: 메뉴·탭·버튼·입력란·안내 메시지 | 기계 대조 대상을 분명히 한다. 브라우저·은행·Google 화면 글자는 큰따옴표로 쓴다 |
| D-11 | **렌더러는 정확한 버전 + SRI로 고정** | CDN 파일이 바뀌어도 앱이 다른 코드를 실행하지 않는다. 해시가 맞지 않으면 로드를 거부하고 원문 표시로 넘어간다 |
| D-12 | **도움말 상태는 루트 컴포넌트 밖** — 모듈 수준 `HelpButton`·`HelpDrawer`가 열림·문서·이동 상태를 갖고, 루트는 맥락 키(`helpKey`)만 계산해 넘긴다 (Check 1차 반영) | 루트 상태로 두면 열고 닫을 때마다 루트가 다시 그려져, 루트 안에서 정의된 `CommentSection`·`GalleryDetailView` 등이 새로 마운트되고 쓰던 댓글·사진 위치가 사라진다(E2E로 확인) |

## 3. 매뉴얼 명세 (`docs/manual/관리시스템.md`)

### 3.1 머리 블록

```markdown
# 관리시스템 사용 매뉴얼

> **대상**: 청년노동자인권센터 대표 (웹 브라우저에서 사용) · **기준일**: YYYY-MM-DD · **범위**: 관리시스템 웹앱 — 메뉴 9개
>
> 예산 집행 등록부터 증빙, 정산·보고서, 일정·게시판·갤러리·뉴스레터·학교관리까지 이 시스템으로 하는 일을 화면 순서와 업무 순서로 안내합니다. 앱 오른쪽 위 「❓ 도움말」을 누르면 지금 보고 있는 화면의 설명이 열립니다.
>
> 이 문서는 사용법 안내서입니다. 회계 규정은 앱의 「📖 회계가이드」, 재단 원문은 수행가이드, 기획 도구는 `docs/manual/사업기획-AI-도우미.md`를 보세요.

## 목차
…(앵커 목차, 견본과 같은 형식)
```

### 3.2 표기 규약

| 규약 | 규칙 | 검사 |
|------|------|------|
| 앱 화면 글자 | 「…」로 쓴다(메뉴·탭·버튼·입력란·메시지). 이모지는 화면 그대로 쓴다(예: 「📥 일괄등록」). 값이 바뀌는 부분은 `…`로 쓴다(예: 「✅ …건 일괄 등록」). 화면에서 태그로 나뉜 글자(예: 「🔒 비밀번호」 뒤의 작은 글씨)나 실행 중에 조합되는 알림 문장은 고정된 부분만 「」에 넣는다(예: 「사업변경신청 마감」) | M1 |
| 앱 밖 화면 글자 | 브라우저·은행·Google 화면 글자는 큰따옴표로 쓴다(예: "팝업 허용") | — |
| 헤딩 | 이모지·코드 표기를 쓰지 않는다(앵커 안정). 번호는 `4.2.3`처럼 쓴다 | M7 |
| 링크 | 문서 안 앵커(`#…`)와 `https://`만 쓴다. 저장소 파일은 링크하지 않고 경로를 코드 표기로 쓴다(앱 안에서는 상대 링크가 깨짐). 이미지는 넣지 않는다 | M6 |
| 예시 값 | 가상값만 쓴다. 수취인은 "㈜가나다인쇄", "다라마케이터링"처럼, 금액은 330,000원처럼 쓴다. 실명·학교 실명·계좌·연락처·사업자번호는 쓰지 않는다 | M4 |
| 재단 표기 | '아름다운재단'은 붙여 쓰고, 재단과 관련해 '후원'을 쓰지 않는다. 단체명은 '청년노동자인권센터' | M5 |
| 근거 주석 | 4장 각 절 첫 줄 아래에 `<!-- src: renderBudget#import -->`처럼 근거 함수·탭 id를 남긴다(화면에는 보이지 않음) | M10 |
| 문체 | 견본과 같이 "~합니다/~하세요", 짧은 문장, 표 우선, 예시는 `> 예시 —` 인용 블록 | 리뷰 |
| 날짜 | 확정 일자는 `YYYY-MM-DD`, 반복 일정은 "매월 10일"처럼 쓴다 | — |

## 5. 앱 내 도움말 명세

### 5.1 사용자 흐름

```
헤더 「❓ 도움말」 클릭
  ├─ 닫혀 있음 → 드로어 열기 + 목표 = HELP_ANCHORS[현재 맥락] (없으면 맨 위)
  │     └─ 문서 상태 idle·error → 불러오기(md fetch → marked 로드 → 렌더)
  └─ 열려 있음 → 닫기 (버튼에 포커스 복귀) — 드로어가 헤더 오른쪽을 덮으므로 마우스로는 「✕」나 Esc로 닫는다

드로어 머리줄: 「목차」(→ 목차 절) · 「이 화면」(→ 현재 맥락 절) · 「✕」(닫기, Esc도 닫기)
본문 안 링크: #앵커 → 드로어 안에서 스크롤 / https → 새 탭
```

- 드로어는 모달이 아니다(배경을 어둡게 가리지 않음). 드로어 밖의 화면은 계속 조작하면서 읽을 수 있고, 드로어가 덮은 오른쪽 영역(넓은 화면에서 520px)은 닫아야 누를 수 있다.
- 처음 열 때 마운트하고, 닫으면 숨기기만 한다(다시 불러오거나 다시 파싱하지 않음). 다시 열면 그때 화면의 절로 이동한다.
- 맥락 키에서 관리자가 아닌 사용자의 `admin` 페이지(대시보드가 그려짐)는 `dashboard`로 본다 (Check 반영).
- 맥락 키는 `currentPage === 'budget' ? 'budget.' + budgetTab : currentPage === 'admin' ? 'admin.' + adminTab : currentPage`로 만든다.

### 5.3 상태·핸들러·이펙트 (`ProjectManagementSystem` 최상위)

```js

const [helpDoc, setHelpDoc] = useState({ status: 'idle', html: '', text: '' });   // idle | loading | ready | error
const [helpTarget, setHelpTarget] = useState({ slug: null, n: 0 });             // n: 같은 slug로 다시 이동해도 이펙트가 돌게
const helpBodyRef = useRef(null), helpDrawerRef = useRef(null), helpBtnRef = useRef(null);

    setHelpDoc({ status: 'loading', html: '', text: '' });
    try {
        const res = await fetch(encodeURI(HELP_MANUAL_URL));
        if (!res.ok) throw new Error(`HTTP ${res.status}`);
        const md = await res.text();
        try { await loadScriptOnce(HELP_MARKED_SRC, HELP_MARKED_SRI); } catch (e) { console.warn('[help] marked 로드 실패 — 원문 표시', e); }
        if (window.marked?.parse) setHelpDoc({ status: 'ready', html: DOMPurify.sanitize(window.marked.parse(md, { gfm: true })), text: '' });
        else setHelpDoc({ status: 'ready', html: '', text: md });
    } catch (e) {
        console.error('[help] 매뉴얼 로드 실패', e);
        setHelpDoc({ status: 'error', html: '', text: '' });
    }
};
const goHelp = (slug) => setHelpTarget(t => ({ slug, n: t.n + 1 }));
const toggleHelp = () => {
    if (helpOpen) { setHelpOpen(false); helpBtnRef.current?.focus(); return; }

    goHelp(HELP_ANCHORS[helpKey] || null);

const onHelpBodyClick = (e) => {
    const a = e.target.closest('a[href^="#"]');
    if (!a) return;
    e.preventDefault();
    goHelp(decodeURIComponent(a.getAttribute('href').slice(1)));

// ① 렌더된 헤딩에 id 부여 (중복은 -1, -2 …), 외부 링크는 새 탭 — ②보다 먼저 선언
useEffect(() => {
    const root = helpBodyRef.current;
    if (!root || !helpDoc.html) return;

    root.querySelectorAll('h1,h2,h3,h4,h5,h6').forEach(h => {
```

- 모든 훅은 `ProjectManagementSystem` 최상위에 둔다(`render*` 안 금지).
- `helpSlug`는 텍스트에서 글자·숫자·공백·하이픈만 남기므로 id에 쓸 수 없는 문자가 들어가지 않는다.
- 구조 변경 (Check 1차, D-12): 위 state·핸들러·이펙트는 루트가 아니라 모듈 수준 `function HelpDrawer({ helpKey })` 안에 있고, 헤더에는 `<HelpButton />`(열림 표시 `aria-expanded`), 레이아웃 끝에는 `<HelpDrawer helpKey={helpKey} />`를 둔다. 둘은 `helpBus`(open·btn·toggle·listeners)로 연결된다. 루트에는 `helpKey` 계산만 남는다.
- 구현 보충 (Check 1차 반영): 닫기는 `closeHelp`로 묶었고, 포커스는 `focus({ preventScroll: true })`로 준다. Esc는 다른 입력이 이미 처리했으면(`e.defaultPrevented`) 무시하고, 포커스가 드로어 안에 있었을 때만 헤더 버튼으로 돌려준다.

### 5.4 slug 규칙 (JS·Python 공통)

1. 헤딩의 렌더된 글자(링크·강조·코드 표시는 글자만)를 앞뒤 공백을 지우고 소문자로 바꾼다.
2. 글자(L)·결합표시(M)·숫자(N)·연결문장부호(Pc)·공백·하이픈이 아닌 문자를 지운다(마침표·괄호·이모지·대시 등).
3. 공백 하나를 하이픈 하나로 바꾼다(연속 공백은 연속 하이픈).
4. 같은 slug가 다시 나오면 문서 순서대로 `-1`, `-2`를 붙인다.

한계: Python 쪽은 마크다운 원문에서 글자를 뽑으므로 단어 안의 `_`나 HTML 엔티티가 든 헤딩에서는 JS와 결과가 달라질 수 있다. 헤딩에 코드 표기를 금지하는 규약(M7)으로 막는다.

검증된 예: "3. 빠른 시작 — 계획서 한 바퀴" → `3-빠른-시작--계획서-한-바퀴`, "8. 산출물 폴더와 brief.md" → `8-산출물-폴더와-briefmd`, "6. 자동 검사(check) 읽는 법" → `6-자동-검사check-읽는-법`.
