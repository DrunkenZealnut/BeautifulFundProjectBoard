| **설계 단계에서의 코드 grep** | "테마 함수가 accent를 참조하는가"를 추측이 아니라 grep으로 확인(`0건`)하여 출력 치환 아키텍처를 확정. 근거 기반 설계 결정의 중요성 확인 |
| **미니 머스타시 파서 기반 구현** | 설계서는 중첩 1단계만 예상했지만, 구현에서 파서 기반으로 무제한 중첩 지원. 템플릿 유연성 향상 (추가 복잡도는 최소) |
| **분리된 selftest + 픽스처** | `promo.py selftest --render` + `_samples/_check-fixture/`로 모든 검증 규칙을 자동화. 다음 산출물 생성 시 빠른 회귀 테스트 가능 |

## 7. 프로세스 개선

### 7.1 Do 단계 교훈

1. **정제 순서의 중요성**: facts.yaml 완성 후 예산 검산 → 단위사업 단계별 정제 → 횡단 주제(메시지, 변경이력) 순으로 진행했을 때 불일치 0 (반대 순서였다면 누락 위험)

2. **kb frontmatter 필수 항목화**: 각 kb md가 facts 어느 부분을 서술하는지 `facts_refs` 메타로 명시 → gap-detector가 검증 용이 (향후 자동 동기화 가능)

3. **개인정보 마스킹을 품질 체크포인트로**: 코드 리뷰 단계가 아니라 kb 정제 단계에 `kb-extract --pii-scan` 통합 → 습관화 필요

### 7.2 Check 단계 교훈

1. **gap-detector의 정량화**: 설계 137항목을 일일이 대조하는 대신 파일별 섹션·함수·메타 체크리스트로 자동화 (현재 수동 목록 → 차기 학습)

2. **C1~C4 같은 "작은 결함"이 누적 기여도 높음**: Match Rate 92% → 95.6%는 5개 결함 수정으로 달성. 각 결함이 0.7%씩 중요

3. **검증 근거 보존의 가치**: selftest 및 픽스처를 커밋해두니 다음 Act 단계에서 즉시 재검증 가능 (다른 기능 개선 후에도 회귀 테스트 용이)

### 7.3 다음 기능에 적용할 사항

- **설계 체크리스트 자동화**: "구현에만 있는 파일/함수/메타" 목록을 grep으로 추출 → 설계서 갱신 항목 자동 제안
- **kb 필수 섹션 명시**: frontmatter에 `required_sections: [A, B, C]`를 선언하면, kb-extract가 누락 검사
- **개인정보 검사를 CI/CD 파이프라인에 통합**: commit hook으로 `kb-extract --pii-scan` 자동 실행
- **출력 스타일 "bkit-pdca-guide" 권장**: Match Rate 수치·섹션별 결과·설계 갱신 항목을 미리 그룹화해서 보고
