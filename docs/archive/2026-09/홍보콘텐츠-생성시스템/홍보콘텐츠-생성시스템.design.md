## 1. Architecture Overview

### 1.1 현재 (Before)

```
data/ (PDF→md 변환본 5건, 표 손상, 변경 전/후 혼재, 개인정보 포함)
  │
  └── 매번 사람이 읽고 → 수치 찾고 → 문서/디자인 툴에서 수작업
```

### 1.2 목표 구조 (After)

```
data/ (원본, 읽기 전용, git 제외)
  │  build_kb (1회 + 변경 시 kb-sync)
  ▼
content/kb/  ── facts.yaml (수치·명칭·날짜 단일 원천)
             ── 01~08 주제별 md (서술·맥락)
  │
  │  /promo brief ──▶ out/<id>/brief.md
  │  /promo draft ──▶ out/<id>/draft.md            ◀── kb + brand + templates/docs
  │  /promo visual ─▶ out/<id>/visual/*.yaml+html  ◀── templates/visual + brand/tokens.css
  │  /promo render ─▶ out/<id>/final/*.png|pdf     ◀── tools/promo.py render (Playwright)
  │  /promo doc ────▶ out/<id>/final/*.hwpx|docx   ◀── hwpx 스킬 / docx 스킬
  │  /promo check ──▶ out/<id>/check-report.md     ◀── tools/promo.py check (facts 대조·PII·표기)
  ▼
content/out/INDEX.md (산출물 대장)
```

### 1.3 설계 원칙

1. **facts 우선**: 금액·횟수·날짜·고유명사는 `facts.yaml`에서만 인용. kb md와 충돌 시 facts가 이김
2. **결정적 렌더**: 같은 `content.yaml` + 템플릿 → 같은 HTML → 같은 PNG. 네트워크·외부 API 0
3. **Claude는 판단, 스크립트는 반복**: 텍스트 생성·요약·어조는 Claude, 치환·렌더·검사·색인은 `promo.py`
4. **산출물은 묶음으로 보존**: brief → draft → content.yaml → html → final을 한 폴더에. 재생성·변형의 출발점
5. **개인정보는 kb에 들어오지 않는다**: 원본(`data/`)에서 kb로 넘어오는 경계에서 마스킹 검사

## 4. `/promo` 스킬 명세

### 4.1 `SKILL.md`

```yaml
---
name: promo
description: "청년노동자인권센터 사업문서 기반 홍보물·문서 생성. 카드뉴스·포스터·리플릿 이미지, 보고서·공문·제안서 HWPX/DOCX, 보도자료·소개글 텍스트. 사용: /promo brief|draft|visual|render|doc|check|kb-sync|status"
argument-hint: "<brief|draft|visual|render|doc|check|kb-sync|status> [args]"
---
```

**라우팅**: `$ARGUMENTS` 첫 토큰으로 서브커맨드 분기. 없으면 `status`. 각 서브커맨드는 시작 시 `content/kb/facts.yaml`을 읽고, `meta.as_of`를 응답 첫 줄에 표시("기준: 2026-08-23 사업변경신청서").

**공통 전제**
- 작업 폴더: `content/out/<id>/`. `<id>`는 brief에서 생성. 이후 서브커맨드는 (a) 인자로 `<id>`, (b) 없으면 `out/`에서 `status != final` 중 최신
- 실행 환경: `content/.venv/bin/python3 content/tools/promo.py …`
- 모든 산출 텍스트에서 숫자·날짜·고유명사는 facts 경로를 주석으로 남김: `<!-- facts: units.campaign.schools -->` (final 변환 시 제거)

### 4.2 서브커맨드 절차

#### `brief <자연어 요청>`

1. 요청에서 `type / audience / unit / templates / channel / deadline` 추론. 확정 불가 항목만 AskUserQuestion (최대 1회)
2. 관련 kb 문서(unit의 `02-단위사업/*.md`, `06-메시지.md`, `08-재단규정.md`)와 facts 경로 열람
3. `<id> = YYYY-MM-DD-<한글슬러그>` 생성 (오늘 날짜 + 요청 핵심어 3어절 이내)
4. `out/<id>/brief.md` 작성 (§3.3). `must_include`에는 audience가 internal이 아니면 항상 `credit_line`
5. 응답: 브리프 요약표 + "다음: `/promo draft`"

#### `draft [<id>]`

1. brief 읽기 → `templates/docs/<템플릿>.md` (type=doc/text) 또는 §4.3 규격표 (type=visual) 로드
2. 초안 작성 규칙: `references/writing-rules.md` 적용 — audience별 어조, 분량, 필수 표현, 금칙
3. visual일 때는 **템플릿별 슬롯 길이 제한**(§5.1)에 맞춰 문안을 짧은/긴 두 버전으로 제시
4. `draft.md` 저장 (기존 있으면 `draft-v{n}.md`), brief `status: draft`
5. 응답: 초안 전문 + 인용한 facts 경로 목록 + "수정 후 `/promo visual` 또는 `/promo doc`"

#### `visual [<id>] [<template>[,<template>]]`

1. draft 확정본 → 템플릿별 `visual/<template>-<nn>.yaml` 작성 (카드뉴스는 페이지당 1파일)
2. `promo.py fill visual/<template>-<nn>.yaml` → `visual/<template>-<nn>.html` (길이 초과 경고 시 슬롯 값을 줄이고 재실행, 최대 2회)
3. brief `status: visual`. 응답: 생성 파일 목록 + 경고 + "다음: `/promo render`"

#### `render [<id>]`

1. `promo.py render out/<id>/visual/*.html --out out/<id>/final/`
2. 결과 PNG(및 `-preview.png`)를 **Read로 열어 시각 검토**: 잘림·겹침·폰트 폴백·빈 슬롯
3. 문제 시 원인(문안 길이 / 템플릿 CSS)을 구분해 보고하고, 문안이면 `visual` 재실행 제안
4. `promo.py check out/<id>` 자동 실행 → `check-report.md`. 통과 시 brief `status: final`, `promo.py index`

#### `doc [<id>] [<hwpx|docx>]`

`references/doc-export.md` 절차:
- **hwpx**: `templates/docs/<종류>.md` 구조 → 사용자 레벨 `hwpx` 스킬 호출. 템플릿 매핑: 공문→`gonmun`, 보고서→`report`, 협력제안서→`proposal`, 안내문→`base`. `.venv`는 `content/.venv` 사용(lxml 포함). `validate.py` 통과 필수
- **docx**: `document-skills:docx` 스킬로 생성. 표는 md 표 그대로 전달
- 출력: `final/<id>.hwpx|docx`. 이후 `check` 실행(텍스트 추출 후 검사)

#### `check [<id>]`

`promo.py check out/<id>` 실행 → 결과 표 출력. FAIL이면 status를 final로 올리지 않음. 규칙은 §7.3.

#### `kb-sync <data/새문서.md>`

1. 새 문서와 `facts.yaml` 비교 → 변경 후보 표 (경로 / 현재값 / 새값 / 근거 줄)
2. AskUserQuestion으로 반영 승인
3. facts 갱신 + `meta.as_of` + `changelog` 추가 + `07-변경이력.md` 섹션 추가 + 관련 `02-단위사업/*.md` 본문 수정 + `deprecated` 갱신
4. `promo.py kb-extract --pii-scan content/kb` 실행하여 개인정보 0건 확인

#### `status`

facts `meta.as_of`, `out/INDEX.md` 요약(status별 개수), 미완(brief/draft/visual) 목록.

## 7. `tools/promo.py` 명세

단일 파일, `argparse` 서브커맨드. 의존: `playwright`, `pyyaml`, `lxml`(hwpx 공용), `pdfplumber`(kb-extract). Python ≥3.11.

### 7.1 `render`

```
promo.py render <html…> [--out DIR] [--scale 2] [--pdf-only] [--timeout 15000]
```

1. 각 HTML의 `<meta name="promo-size">`로 뷰포트 결정 (없으면 1080×1080), `promo-print` 있으면 인쇄 모드
2. `sync_playwright` → chromium (headless, `device_scale_factor=scale`) → `page.goto(file://…)`
3. 대기: `wait_for_load_state('load')` → `page.evaluate('document.fonts.ready')` → `wait_for_function('document.fonts.status === "loaded"')` → 이미지 `complete` 확인
4. 출력
   - 일반: `page.screenshot(path=<out>/<basename>.png, clip=viewport)`
   - 인쇄: `page.emulate_media('print')` → `page.pdf(path=<out>/<basename>.pdf, format='A4', print_background=True, prefer_css_page_size=True)` + `emulate_media('screen')` 후 첫 페이지 `<basename>-preview.png`
5. 종료 코드: 전부 성공 0, 하나라도 실패 1 (실패 파일·사유를 stderr에 표로)
6. 폰트 폴백 감지: `document.fonts.check("16px Pretendard")`가 false면 경고 출력

### 7.2 `fill`

```
promo.py fill <slots.yaml…> [--templates content/templates/visual]
```

1. yaml의 `template` → `<templates>/<template>.html` 로드
2. 미니 머스타시: `{{key}}`(이스케이프), `{{{key}}}`(raw), `{{#list}}…{{/list}}`(반복, 내부 `{{field}}`), `{{^key}}…{{/key}}`(비어 있을 때). 중첩 1단계까지
3. `<meta name="promo-slots">` 파싱 → 길이 초과 슬롯을 `WARN slot=title len=23 max=18`로 출력 (종료 코드 0, `--strict`면 1)
4. `href="../../brand/…"` 상대경로를 `file://` 절대경로로 치환(렌더 안정성)
5. 로고 슬롯: 값이 파일 경로이고 존재하면 `<img>`, 아니면 `{{^logo_org}}` 폴백 블록 활성
6. 출력: 같은 이름 `.html`

### 7.3 `check`

```
promo.py check <out/<id>> [--facts content/kb/facts.yaml] [--strict]
```

검사 대상: `draft*.md`, `visual/*.yaml`, `visual/*.html`, `final/*.hwpx`(text_extract) , `final/*.docx`(python-docx 없으면 skip 경고).

| 규칙 | 조건 | 결과 |
|------|------|------|
| R1 PII | `01[016789]-?\d{3,4}-?\d{4}`, 이메일, `\d{6}-[1-4]\d{6}`, `직인` 파일명 | FAIL |
| R2 deprecated | `facts.deprecated[].text` 포함 (brief.audience ≠ internal, 07-변경이력 인용 블록 제외) | FAIL |
| R3 credit | `must_include`에 credit_line인데 최종 텍스트에 `program.credit_line` 없음 | FAIL |
| R4 금액 | `\d{1,3}(,\d{3})+원` 패턴의 금액이 facts 내 금액 집합에 없음 | WARN |
| R5 날짜 | `YYYY.MM.DD`/`M/D` 패턴 날짜가 facts 이벤트·기간에 없음 | WARN |
| R6 단체명 | `청년노동자 인권센터`, `청년노동인권센터` 등 오표기 | FAIL |
| R7 슬롯 | visual yaml 필수 슬롯 빈 값 | WARN |

출력: `check-report.md` (규칙·파일·줄·발췌 표 + 요약) + stdout 요약. FAIL ≥1 → 종료 코드 1.

### 7.4 `index`

`out/*/brief.md` frontmatter + `check-report.md` 마지막 요약 → `out/INDEX.md` 재생성 (§3.5). 최신순 정렬.

### 7.5 `kb-extract`

```
promo.py kb-extract pdf <file.pdf> [--pages 1-20] --out content/kb/_raw/<name>.md
promo.py kb-extract tables <file.md> --out content/kb/_raw/<name>-tables.md   # HTML <table> → md 표
promo.py kb-extract --pii-scan content/kb                                    # R1 규칙 스캔, 0건이면 0
```

`_raw/`는 정제 작업용 임시 폴더 (git 제외 목록에 추가).
