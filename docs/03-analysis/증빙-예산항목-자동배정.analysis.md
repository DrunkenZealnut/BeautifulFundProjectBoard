## 3. 결함

| # | 심각도 | 내용 |
|:-:|:-:|---|
| D-1 | 🟡 | 규칙 배정 수취인을 이번 건만 다른 항목으로 바꿔도 `_saveRule` 기본 true → 등록 시 기존 `exact` 규칙을 조용히 덮어씀. 원 규칙이 `biz_no`/`contains`면 우선하는 새 `exact` 규칙이 생김 |
| D-2 | 🟡 | 단건 폼: 규칙 배정 후 수취인만 고치면 `autoAssignForm`이 조기 반환해 `formAssign.source='rule'`이 남음 → 잘못된 📌 배지, 규칙 저장 체크박스 숨김, 엉뚱한 규칙 `hit_count` 증가 |
| D-3 | 🟡 | 엑셀 소스가 입금/출금 구분 없이 자동배정 → 이력 있는 거래처의 **입금**(환불 등)이 기본 선택된 채 지출로 등록될 수 있음 (F-14까지는 수동 매핑이라 드러나지 않음) |
| D-4 | 🟢 | PDF 행 수취인 타이핑 중 글자마다 재해석 → 입력 도중 배정·`_saveRule` 초기화 (수수료 행 포함) |
| D-5 | 🟢 | 프로젝트 규칙과 `project_id NULL` 규칙이 같은 패턴일 때 우선순위 미정의. NULL 규칙 수정 시 `project_id`가 현재 프로젝트로 바뀜 |
| D-6 | 🟢 | 규칙 편집에서 `contains` 규칙 표시명 변경 시 직접 입력한 포함 패턴이 지워짐 |
| D-7 | 🟢 | `UNIQUE NULLS NOT DISTINCT`는 PG15+ 전용 — 마이그레이션 상단에 요구 버전 명시 필요 |

**확인됨(문제 없음)**: render/IIFE 안 훅 없음(`useEffect`는 최상위) · TDZ 없음 · 수수료 행 전파 정상 · `project_id NULL` upsert on-conflict 정상(PG15+).
