# 입금확인증 PDF 집행등록 (F-14) — 은행 입금확인증 PDF에서 날짜·금액·수취인·적요를 추출해 예산집행내역에 자동 등록

> **Summary**: 은행 입금확인증 PDF를 업로드하면 브라우저 안에서 텍스트를 추출·파싱하여 집행일·금액·수취인·집행내용을 일괄등록 미리보기에 자동으로 채우고, 예산항목만 지정하면 집행내역 등록과 동시에 해당 PDF를 이체 증빙으로 첨부한다.
>
> **Project**: 아름다운재단 2026 공익단체 인큐베이팅 지원사업 관리시스템
> **Feature ID**: F-14
> **Author**: Claude Code

## Executive Summary

| Perspective | Content |
|-------------|---------|
| **Problem** | 계좌이체 집행 1건마다 은행 입금확인증 PDF를 열어 날짜·금액·수취인·적요를 눈으로 읽고 폼에 옮겨 적은 뒤, 같은 PDF를 증빙으로 다시 첨부해야 한다. 오타·중복등록·증빙 누락이 생기기 쉽고 캠페인 1회당 여러 건을 처리하면 반복 작업이 크다 |
| **Solution** | 일괄등록 탭에 "입금확인증 PDF" 소스를 추가. pdf.js(CDN)로 브라우저 내에서 텍스트를 추출하고 라벨 별칭 테이블 기반 파서로 `거래일시→집행일`, `입금금액→금액`, `수취인성명→수취인`, `출금통장표시내용→집행내용`을 뽑아 기존 미리보기 표에 자동 채움. 등록 시 PDF를 `attachments` 스토리지에 올리고 `documents`에 이체 증빙으로 연결 |
| **Function/UX Effect** | 폴더의 PDF 여러 장을 한 번에 선택 → 건당 2~3분 걸리던 입력이 예산항목 선택 10초로 단축. 동일 날짜·금액·수취인 기존 건은 "중복 의심" 경고로 이중 등록 방지. 계좌번호는 화면·DB 어디에도 남기지 않음 |
| **Core Value** | 이체확인증(재단 필수 증빙)과 집행내역이 등록 시점에 1:1로 연결되어 정산 시 증빙 누락 0건, 입력 오류 최소화. PDF·텍스트가 브라우저 밖으로 나가지 않아 개인정보(계좌번호) 유출 위험 없음 |

## 1. 현황 분석

### 1.1 현재 집행 등록 경로 (index.html)

| 경로 | 위치 | 입력 방식 | 증빙 첨부 |
|------|------|-----------|-----------|
| 단건 등록 폼 | `budgetTab === 'register'` (~line 9210) | 분류·항목·금액·결제방법·집행일·수취인·집행내용 수동 입력 | `formDocFiles` → `attachments` 스토리지 + `documents` insert (~line 9468) |
| 은행 엑셀 일괄등록 | `budgetTab === 'import'` (~line 9558) | xlsx/csv → 열 매핑(날짜/금액/구분/이름) → 미리보기 표에서 소분류·항목·설명·결제방법 지정 → insert | **없음** |

일괄등록은 `bankImportStep` (`upload | preview | done`), `bankImportRows`, `bankColMap`, `bankHeaders` 4개 state로 동작하며, 행 단위 소분류/예산항목 select와 `getAllSubcategories()`/`getAllBudgetItems()` 헬퍼를 이미 갖추고 있다.

### 1.2 문제점

1. **이중 작업**: PDF를 보고 폼에 옮긴 뒤 같은 PDF를 증빙으로 또 첨부해야 함
2. **일괄등록에 증빙 첨부 없음**: 엑셀 일괄등록으로 넣은 건은 나중에 집행내역 탭에서 건별로 증빙을 올려야 함
3. **오류 유형**: 금액 오타, 날짜 착오(이체일 ≠ 등록일), 동일 건 이중 등록
4. **재단 정산 요구**: 계좌이체 건은 유형별로 `이체내역서`/`이체확인증`/`이체증`이 필수 증빙 (`DOCUMENT_RULES`, ~line 3195) — 등록과 증빙이 분리되면 누락이 발생

### 1.3 샘플 PDF 구조 분석 (신한은행 인터넷뱅킹 「입금확인증」)

사용자 제공 샘플 1건 분석 결과 (개인정보는 기록하지 않음):

| 항목 | 값 |

## 3. 구현 범위

### 3.1 In Scope

- [ ] pdf.js CDN 스크립트 태그 추가 (`pdfjs-dist@3.11.174` legacy UMD `pdf.min.js` + `workerSrc` 설정)
- [ ] 최상위 순수 함수: `extractPdfTextLines(file)`, `parseDepositConfirmation(lines)`, `DEPOSIT_PDF_LABELS` 별칭 테이블 (신한 우선, 타 은행 별칭 동봉)
- [ ] 일괄등록 탭 소스 선택 UI + PDF 업로드 단계 + 파싱 진행 표시
- [ ] 미리보기 표: PDF 행 자동 채움, 배지(중복 의심/인식 실패/은행명), 값 편집
- [ ] 등록 시 PDF 증빙 업로드 + `documents` insert
- [ ] 단건 등록 폼 자동입력 버튼 (FR-09)
- [ ] `vercel.json` CSP `worker-src` 추가
- [ ] CLAUDE.md 갱신 (일괄등록 탭 설명, 파서 위치)

### 3.2 Out of Scope

- 스캔본·이미지 PDF의 OCR (Claude Vision 등 서버 처리) — 텍스트 없는 PDF는 FR-08로 수동 입력 안내. 후속 단계 후보
- 은행 거래내역서(다건 명세) PDF 파싱 — 이는 엑셀 일괄등록 경로 유지
- 승인 워크플로·집행내역 탭·보고서 로직 변경
- DB 스키마 변경 (기존 `budget_executions`·`documents` 컬럼으로 충분, 마이그레이션 없음)
- 세전 환산 표시·자동 등록 (Q1 결정: 확인증 금액 = 실지급액을 그대로 등록)

## 4. 성공 기준

### 4.1 Definition of Done

- [ ] 샘플 PDF 업로드 시 `2026-09-18` / `96968` / 수취인 / `인천캠페인0917`이 편집 없이 정확히 채워짐
- [ ] PDF 5장 동시 업로드 → 5행 생성, 소분류·항목 지정 후 일괄 등록 성공
- [ ] 등록된 각 건의 집행내역 탭 증빙 목록에 PDF가 이체 증빙명으로 표시·다운로드 가능
- [ ] 같은 PDF 재업로드 시 `중복 의심` 배지 + 선택 해제
- [ ] 텍스트 없는 PDF(이미지로 인쇄한 파일)는 `인식 실패` 행으로 남고 수동 입력 후 등록 가능
- [ ] 단건 폼 자동입력 버튼으로 4개 필드 채움 + 증빙 슬롯에 PDF 첨부 표시
- [ ] 엑셀 일괄등록·단건 등록·집행내역 탭 회귀 없음
- [ ] 브라우저 콘솔에 계좌번호가 출력되지 않음, 네트워크 탭에 PDF 텍스트 전송 없음
- [ ] Vercel 배포 후 CSP 위반 로그 없음

### 4.2 품질 기준

- [ ] Babel 블록 문법 오류 없음 (`http.server`로 페이지 로드 확인)
- [ ] `render*()` 내부 훅 사용 없음
- [ ] 파서는 입력(줄 배열) → 출력(필드 객체) 순수 함수로 브라우저 콘솔에서 단독 테스트 가능
