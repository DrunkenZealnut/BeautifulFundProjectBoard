# 증빙 예산항목 자동배정 (F-15) — 이체대상·거래처를 예산항목과 연결해 이체확인증·영수증·세금계산서 입력 시 예산항목을 자동 배정

> **Summary**: 이체대상(수취인)·거래처(공급자)와 예산항목(소분류·항목)을 잇는 규칙표를 두고, 이체확인증 PDF·전자세금계산서 PDF·영수증 이미지를 올리면 필드를 추출한 뒤 규칙 → 과거 집행이력 순으로 예산항목을 자동 배정한다. 이미 등록된 집행 건과 같은 거래로 보이면 새로 등록하지 않고 그 건에 증빙으로 붙인다.
>
> **Project**: 아름다운재단 2026 공익단체 인큐베이팅 지원사업 관리시스템
> **Feature ID**: F-15
> **Author**: Claude Code
> **Date**: 2026-09-24
> **Status**: Draft
> **Related**: F-14 입금확인증 PDF 집행등록 (`docs/archive/2026-09/입금확인증-PDF-집행등록/`), `DOCUMENT_RULES`, 수급자 관리(`recipients`)

## Executive Summary

| Perspective | Content |
|-------------|---------|
| **Problem** | F-14로 이체확인증의 날짜·금액·수취인은 자동으로 채워지지만, 예산항목(소분류·항목)은 여전히 행마다 직접 골라야 한다. 같은 강사·같은 업체에 반복 지급하는데도 매번 선택하고, 세금계산서·영수증은 파싱 경로가 아예 없어 수동 입력 + 수동 첨부다. 이체확인증과 세금계산서가 같은 거래인데 두 번 등록될 위험도 있다 |
| **Solution** | ① `bf.payee_budget_rules` 규칙표(수취인명/사업자번호 → 소분류·항목·유형) ② 규칙이 없으면 과거 집행이력에서 같은 수취인의 최빈 항목을 추천하는 `resolveBudgetAssignment()` ③ 증빙 종류 자동 판별 업로드: 이체확인증(F-14 파서), 홈택스 전자세금계산서 PDF(브라우저 파서), 영수증 사진·스캔본(`api/receipt-ocr.py`, Claude 비전) ④ 기존 집행 건 매칭 시 "이 건에 증빙 첨부"로 전환 |
| **Function/UX Effect** | 증빙 파일만 끌어다 놓으면 날짜·금액·거래처·예산항목이 채워진 미리보기가 나오고 확인 후 등록만 누르면 된다. 배정 근거가 배지(📌규칙 / 🕘이력 / ❓미배정)로 보이며, 등록할 때 「이 거래처를 규칙으로 저장」을 체크하면 다음부터는 자동이다. 항목 예산을 초과하면 등록 전에 경고한다 |
| **Core Value** | 반복 거래의 예산 분류가 매번 같아져 정산 때 항목이 흔들리지 않는다(재단 보고 신뢰도). 증빙 종류와 관계없이 등록과 증빙 첨부가 한 번에 끝나고, 같은 거래가 두 번 잡히는 일이 없다 |

## 1. 현황 분석

### 1.1 현재 경로와 한계

| 경로 | 필드 자동입력 | 예산항목 배정 | 증빙 첨부 |
|------|---------------|---------------|-----------|
| 단건 등록 폼 (`budgetTab === 'register'`) | 입금확인증 PDF만 (F-14) | 수동 | 수동/자동(PDF) |
| 일괄등록 PDF (`bankImportSource: 'pdf'`) | 입금확인증 (F-14) | **수동** — 행마다 소분류·항목 select | 자동 (이체확인증) |
| 일괄등록 엑셀 (`bankImportSource: 'excel'`) | 열 매핑 | **수동** | 없음 |
| 집행내역 탭 재첨부 | — | — | 수동 |
| 세금계산서·영수증 | **없음** | 수동 | 수동 |

### 1.2 데이터 구조 (현재)

- `bf.budget_executions`: `subcategory_id`/`subcategory_name`/`category_name`/`budget_item_id`/`budget_item_name`/`type`(비목) + `recipient`(자유 문자열) + `project_id`. 수취인·거래처를 가리키는 키가 없다 → 규칙 매칭은 **이름 정규화 문자열** 기준이 된다
- 예산 구조는 `activeBudgetData`(프로젝트별 `projects.budget_data` JSONB, 없으면 하드코딩 `BUDGET_DATA`). 항목 `id`는 프로젝트 안에서 고유 → 규칙은 `project_id` 범위로 저장해야 연도 전환 후 깨지지 않는다
- `bf.recipients`: 개인 수급자 프로필(생년월일·주소·전화 포함 PII). 거래처 규칙과 성격이 다르므로 **재사용하지 않고 별도 테이블**로 둔다 (규칙표에는 PII 없음)
- `DOCUMENT_RULES[type]`: 비목별 필수 증빙 — 세금계산서는 `base`의 `(전자)세금계산서`, 영수증은 `required`의 `영수증` 슬롯에 대응
- F-14 공용 헬퍼: `extractPdfTextLines`, `parseDepositConfirmation`, `findDuplicateExecution`, `uploadExecutionDoc`, `insertExecutionDocs`, `pickTransferDocName`, 미리보기 `updateRow(ri, patch)`

### 1.3 문제점

1. **반복 선택**: 같은 강사(자문비)·같은 인쇄소(홍보물 제작)·같은 대관처(회의비)에 여러 번 지급하는데 매번 소분류·항목을 고른다
2. **세금계산서·영수증 경로 없음**: 카드 결제 건과 업체 거래 건의 주 증빙인데 전부 손입력
3. **이중 등록 위험**: 업체 거래는 이체확인증 + 세금계산서가 짝으로 존재한다. 둘을 따로 올리면 집행 2건이 생긴다 (F-14 중복검사는 날짜·금액·수취인 완전일치만 보며, 세금계산서 작성일 ≠ 이체일인 경우를 못 잡는다)
4. **분류 불일치**: 같은 거래처가 시기마다 다른 항목으로 잡히면 항목별 집행률·정산보고서가 틀어진다

## 3. 설계 결정

| # | 결정 | 근거 |
|---|------|------|
| D-1 | 규칙 키는 `recipient` 정규화 문자열 + (있으면) 사업자번호 | 집행 테이블에 거래처 FK가 없고, 기존 데이터를 마이그레이션 없이 이력으로 쓰려면 문자열 매칭이 필요. 사업자번호는 업체 동명이인·상호 표기 차이를 해결 |
| D-2 | `recipients`와 별도 테이블 | `recipients`는 원천징수·급여명세용 개인 PII. 거래처 규칙은 업체도 포함하고 PII가 없어 권한·노출 범위가 다르다 |
| D-3 | 규칙 > 이력 > 미배정, 사용자 수정값 불변 | 명시 규칙이 가장 예측 가능. 이력은 규칙 입력 부담을 줄이는 보조. 자동값이 사람 선택을 덮으면 신뢰를 잃는다 |
| D-4 | 텍스트 PDF는 브라우저, 이미지만 서버 OCR | F-14 원칙(가능하면 브라우저 밖으로 안 나감) 유지, 비용은 필요한 곳에만 |
| D-5 | OCR 모델은 `claude-sonnet-5`, 출력은 JSON 스키마 강제 | 영수증 한글 인식 정확도·속도·비용 균형. 파싱 실패 시 빈 값 + ⚠ 표시로 폴백 |
| D-6 | 증빙이 기존 건과 맞으면 첨부가 기본값 | 업체 거래의 이체확인증+세금계산서 이중 등록을 구조적으로 막는다 |

## 6. 위험과 대응

| 위험 | 대응 |
|------|------|
| 홈택스 세금계산서 PDF의 텍스트 레이아웃이 발급 경로마다 다름 | 실제 샘플 2~3건으로 Design 단계에서 라벨 표 확정. F-14처럼 라벨 스캔 + 글자 사이 공백 허용 정규식 재사용 |
| 동명이인 개인 수취인(예: 같은 이름의 강사 2명) | 개인은 `exact` 규칙만, 이력 후보가 갈리면 자동배정하지 않고 후보 드롭다운만 표시 |
| OCR 오인식(금액 자릿수) | 금액·날짜는 항상 편집 가능 + `⚠ AI 인식` 배지, 기존 건 매칭은 금액 완전일치만 인정해 오인식 건이 잘못 합쳐지지 않게 |
| 규칙이 가리키는 항목이 예산 변경으로 사라짐 | 해석 시 항목 존재 확인, 없으면 규칙 무시 + 규칙 탭에 `⚠ 항목 없음` 표시 |
| Babel 단일 파일 비대화 | 파서·해석기는 모듈 수준 순수 함수로 분리, OCR은 `api/`로 |

## 7. 성공 기준

- [ ] 규칙이 있는 거래처의 증빙을 올리면 소분류·항목이 수동 선택 없이 채워진다 (규칙 적중 100%)
- [ ] 규칙 없이도 과거 2회 이상 같은 항목으로 등록된 수취인은 이력으로 배정된다
- [ ] 홈택스 전자세금계산서 샘플 PDF에서 작성일자·공급자·합계금액이 정확히 추출된다
- [ ] 영수증 사진 샘플에서 날짜·상호·합계가 추출되고 실패 시 수동 입력으로 계속할 수 있다
- [ ] 이미 등록된 이체 건에 같은 거래의 세금계산서를 올리면 신규 등록이 아닌 증빙 첨부가 기본 선택된다
- [ ] 계좌번호·카드번호가 state·DB·콘솔 로그에 남지 않는다
- [ ] 기존 F-14 일괄등록·단건 자동입력 동작이 회귀하지 않는다
