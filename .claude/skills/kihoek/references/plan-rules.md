## 2. 예산표 규칙 (R4b)

```
| 계정항목 | 금액 | 산출근거 |
|---|---:|---|
| 사업인건비 | 1,200,000원 | 4회×300,000 <!-- facts: unit_costs.lecture_fee --> |
| **소계** | **1,200,000원** | |
| 예비비 | 500,000원 | 500,000×1 <!-- facts: program.budget.reserve --> |
| **합계** | **1,700,000원** | |
```

- 계정명은 `08-재단규정.md#4`·`03-예산.md`의 계정명만 (사업인건비·사업회의비·도서인쇄비·지급수수료·여비교통비·물품구매비·사업홍보비·예비비 / 운영인건비·일반관리비·임차료·교육훈련비·홍보비).
- 산출근거는 `수량×단가` 식. 곱셈 기호 `×`, 덧셈 `+`, 괄호 허용. 범위(`3~4회`)·배수어(`1천만원`)·나눗셈·뺄셈은 검산할 수 없으니 쓰지 않는다. 합계 행은 표 맨 끝에 — 합계 뒤 항목은 경고. 단가는 `unit_costs.<id>`를 주석으로. `note: 미확인` 단가를 쓰면 상단 `⚠ 규정` 블록에 "미확인 단가" 목록.
- 새 단가(unit_costs에 없음)는 금액 뒤 `(신규 단가 — 확인 필요)`. 표 밖 파생 금액은 `10,000,000원(산출: 5,000,000×2)` — **곱·합만**. 나눗셈(`/`)·범위(`3~4`)·배수어(`1천만`)는 검산할 수 없다 — 표 안에서는 `R4b 파싱` WARN, `(산출:)` 표식에서는 파싱 불가·값 불일치 모두 FAIL. 식 안 괄호는 1단계까지(`(산출: (1,700,000+500,000)×2)`).
- 소계 = 그룹 항목 합, 합계 = 소계 합 + 소계 밖 행(예비비). 소계·합계는 정확 일치, 항목 행은 0.1% 허용오차.

## 5. check 루프와 doc

1. `promo.py check content/out/<id>` — FAIL이면 해당 줄을 고쳐 재검사(최대 2회). R8 FAIL(경로 없음)은 facts에 실제로 있는 경로로, R4 FAIL은 unit_costs 인용 또는 표식으로, R9 FAIL은 헤딩 이름을 골격 표기로.
2. PASS → brief `status: draft`. 응답에 check 결과 표 요약(FAIL/WARN 수 + WARN 사유).
3. `doc`: `promo.py doc-stamp content/out/<id>` (출력 `doc-stamp  <draft 파일> <sha1>` — 변환은 반드시 이 파일로) → `content/tools/md2hwpx.py content/out/<id>/<그 draft 파일> --template report --output content/out/<id>/final/<id>.hwpx --title "…"` (`/promo doc` 절차) → `promo.py check` PASS → `status: final` → `promo.py index`. 재단 양식 hwpx가 있으면 hwpx 스킬 레퍼런스 모드.

## 6. review 에서의 쓰임

`review --as plan|proposal`은 위 §2~§4를 대상 초안에 적용해 표로 보고한다. 파일은 고치지 않는다.
